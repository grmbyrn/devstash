- 2026-07-09 — **Auth Setup — NextAuth + GitHub Provider (Phase 1)** (Completed). Stood up NextAuth v5 (`next-auth@^5.0.0-beta.31`) + `@auth/prisma-adapter@^2.11.2` using the split-config pattern. `src/auth.config.ts` holds the edge-safe base (GitHub provider only, no adapter); `src/auth.ts` builds the full instance — `PrismaAdapter` over the existing `@/lib/prisma` singleton, `session: { strategy: "jwt" }`, and `jwt`/`session` callbacks that thread the user id onto `session.user.id`. `src/app/api/auth/[...nextauth]/route.ts` re-exports `GET`/`POST` from `handlers`; `src/proxy.ts` uses the named `export const proxy = auth(...)` with a `/dashboard/:path*` matcher, redirecting unauthenticated requests to NextAuth's default `/api/auth/signin` (no custom `pages.signIn`). `src/types/next-auth.d.ts` augments `Session.user.id` and the JWT. Verified against the running dev server: `/dashboard` + `/dashboard/collections` → 302 to `/api/auth/signin`, `/` stays 200 (outside matcher), the default sign-in page renders "Sign in with GitHub", and `/api/auth/providers` reports GitHub with the correct callback URL. The full GitHub OAuth round-trip (login → redirect back to `/dashboard`) still needs a manual browser pass. Lint + build pass. Shipped on branch `feat/auth-nextauth-github`. Spec: @context/features/auth-phase-1-spec.md.
